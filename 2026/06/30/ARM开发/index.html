ARM指令

1. __get_LR()

在 ARM 架构中，当发生函数调用（如执行 BL 指令）时，处理器会自动将下一条指令的地址（即返回地址）保存到链接寄存器（LR，通常是 r14）中。因此，__get_LR() 获取到的正是调用者发起调用时的返回地址。
仅获取地址：它返回的只是一个内存地址（裸指针），而不是函数名或代码行号。
架构绑定：这是 ARM 特有的寄存器概念，在 x86/x64 架构中，返回地址是保存在栈（Stack）上的，没有专门的 LR 寄存器。

如果要找到函数名使用 *dladdr()*：在 Linux 环境下，可以将 __get_LR() 获取到的地址传给 dladdr()，它会返回该地址所在的共享库名称和符号名（函数名）。

X86环境：在MSVC编译器中使用_ReturnAddress()可以返回x86堆栈中调用者的地址

ARM硬件

1.ITCM & DTCM

TCM 的全称是 Tightly Coupled Memory（紧耦合存储器）。它是直接集成在 CPU 芯片内部、物理上紧耦合于 CPU 核心的一种高速片上 SRAM。根据功能的不同，TCM 被划分为两个独立的物理模块：ITCM 和 DTCM。

  1. ITCM (Instruction TCM - 指令紧耦合内存)
    主要功能：专门用于存放需要高速执行的程序代码（指令）。
    应用场景：通常用于存放中断服务程序（ISR）、启动引导代码（Bootloader）、RTOS 内核调度器，以及对实时性要求极高的算法（如电机 PID 控制、FFT 运算等）。
    优势：CPU 可以直接从 ITCM 取指，实现零等待状态，确保关键代码的执行时间完全可预测。
  2. DTCM (Data TCM - 数据紧耦合内存)
    主要功能：专门用于存放高频访问的程序数据。
    应用场景：常用于存放堆栈（Stack）、全局变量、实时任务控制块（TCB）、DMA 描述符以及时间敏感的传感器缓冲区数据。
    优势：CPU 访问 DTCM 的速度与访问寄存器相近，能够避免因 Cache 污染或写回策略导致的数据访问抖动

TCM 与 DTCM 的核心特性与协同优势

  1. 并行访问：ITCM 和 DTCM 在物理上是分离的，且通过独立的专用总线直连 CPU 内核。这意味着 CPU 在从 ITCM 获取指令的同时，可以并行从 DTCM 读写数据，彻底避免了总线竞争，大幅提升流水线效率。
  2. 非缓存机制（Cacheless）：TCM 不属于 Cache 层级体系，不经过 Cache 控制器。因此它没有 Cache 的命中/缺失概率问题，完全由软件手动管理，数据 100% 可控且常驻不丢失。
  3. 容量限制：由于物理上紧耦合于内核，TCM 的容量通常较小，一般在几 KB 到几百 KB 之间（例如 STM32F7 提供 16KB ITCM 和 128KB DTCM）。

tips： 在使用 DTCM 时，开发者必须注意一个重要的硬件限制：DMA（直接内存访问）控制器通常无法访问 TCM。因为 TCM 是 CPU 内核专属的直连内存，不挂载在系统总线上。因此，绝对不能将需要 DMA 搬运的数据（如大型通信缓冲区、图像帧数据）或局部变量（存放在栈中）分配在 DTCM 中，否则 DMA 传输会失败或产生总线错误

2.I-cache & D-cache

这两个cache属于是cpu的L1 cache层级，分别是指令（I）cache和数据（D）cache

它们的核心作用是作为 CPU 和主内存（RAM）之间的“缓冲池

  1. I-Cache（指令缓存）
    功能：专门用来缓存 CPU 即将要执行的机器指令（代码）。
    特点：它是只读的。CPU 只需要从中读取指令，不需要写入。
    优势：通过缓存指令，CPU 在顺序执行代码或进行循环时，不需要频繁去主内存拉取指令，从而保证了指令流水线的顺畅。
  2. D-Cache（数据缓存）
    功能：专门用来缓存程序运行中频繁读写的变量、数组、结构体等数据。
    特点：它是可读可写的。
    复杂性：因为涉及写入，D-Cache 存在一致性问题。当 CPU 修改了 D-Cache 里的数据，但还没来得及写回主内存时，如果此时 DMA 或另一个 CPU 核心去读主内存，就会读到旧数据。因此，D-Cache 需要复杂的机制（如 Write-Back、Cache Coherence 协议）来保证数据的一致性。

Cache与TCM的比较

特性 I-Cache / D-Cache ITCM / DTCM
工作机制 硬件自动管理。CPU 自动判断哪些数据需要缓存，对程序员透明。 软件手动管理。程序员必须通过链接脚本（Linker Script）显式指定哪些代码/数据放在 TCM 中。
访问延迟 不确定。命中（Hit）时极快，未命中（Miss）时需要等待主内存，产生抖动。 绝对确定。无论何时访问，延迟永远是固定的（通常 1-2 个时钟周期）。
容量大小 较大。通常在几 KB 到几十 MB 之间（如 L1、L2、L3）。 较小。通常只有几 KB 到几百 KB。
适用场景 通用的程序加速，适合绝大多数常规代码和数据。 对实时性（Real-time）要求极其苛刻的场景（如电机控制算法、中断响应、RTOS 调度）。
DMA 访问 可以。D-Cache 挂载在系统总线上，DMA 可以访问（但需注意一致性）。 不可以。TCM 是 CPU 内核专属直连的，DMA 无法访问。

3.DAC

DAC是访问DTCM的模块，也就是7700H中的mailbox

Mailbox，内部称为 DAC（DTCM Access Control），它除了可以访问 DTCM，还可以访问 FastMemory。DAC 模块位于 CPU 和硬件加速模块之间，用于硬件加速模块和 CPU 之间的数据传输与控制。为了实现正常的数据传输，需要支持 DAC 与 CPU 间的链路控制和数据传输、DAC与硬件模块间的链路控制和数据传输。即 DAC 提供了 CPU 与 HW 之间的数据传输、队列映射、链路控制、状态查询等功能。

4.AXI总线

AXI是ARM芯片内部的数据传输通路协议
AXI（Advanced eXtensible Interface，高级可拓展接口）是由 ARM 公司提出的一种高性能、高带宽、低延迟的片上总线协议。

AXI总线特点

  • 分离的读写通道：AXI 将地址/控制信号与数据信号完全分离，并且读、写数据通道相互独立。这种单向通道的体系结构使得读写操作可以同时进行（全双工），大幅减少了传输延时。
  • 五通道独立握手：AXI 定义了 5 个独立的信号通道（读地址通道、读数据通道、写地址通道、写数据通道、写响应通道）。每个通道都使用独立的 VALID/READY 信号进行握手，确保数据传输的可靠性与灵活性。
  • 突发传输（Burst）：支持基于突发模式的数据传输，只需发送首地址即可连续传输多块数据，有效减少了单次传输的初始化开销，提高了带宽利用率。
  • 乱序与未完成（Outstanding）传输：主设备可以在未收到前一个事务返回数据的情况下，连续发起多个读写请求；从设备也可以根据事务 ID（AxID）乱序返回数据，从而极大提升了流水线处理效率。

AXI总线现在最主流的是AXI4系列

  • AXI4（Full）：全功能版本，支持高性能的内存映射通信和长突发传输（最高支持 256 次数据传输），通常用于处理器与高速存储器之间的大数据量传输。
  • AXI4-Lite：轻量级简化版本，不支持突发传输，仅支持单次数据读写。由于其协议简单、资源占用小，主要用于访问低速外设的控制寄存器等低带宽通信场景。
  • AXI4-Stream：专为连续数据流设计的接口，去掉了地址通道，仅保留数据通道。它支持高吞吐量的流式传输，广泛应用于音视频处理、DMA 数据搬运等场景。

具体使用，例如，对于SSD而言，从PCIe下来的数据需要传给core进行处理，所以PCIe下来的数据会走到AXI总线上。

ex. CPU 作为 AXI 总线的主设备（Master），向挂载在 AXI 总线上的 PCIe 控制器（Slave）发送读写请求。PCIe 控制器接收到 AXI 请求后，将其“翻译”成 PCIe 协议报文，再通过 PCIe 链路发送给下游的 PCIe 设备

attribute(section())

将变量或函数强制放置到指定的内存段（section）中，而非默认的 .data 或 .bss 段。这种技术常用于嵌入式系统、操作系统内核或需要精确控制内存布局的场景。

  • 这是 GCC/Clang 提供的编译器属性，用于指定变量或函数应被链接器放置在哪个自定义段中。

aligned(x) 和 packed

具体使用是

  • **aligned(x)**：强制对齐 —— 要求变量或结构体的起始地址必须是 x 的整数倍，通常会增加填充字节，以满足对齐要求。
  • **packed**：取消对齐 —— 告诉编译器不要插入任何填充字节，成员之间紧密排列，以节省空间，但可能牺牲访问效率。

gcc上可以使用aligned和packed，但是windows上使用的一般是MSVC，MSCV要实现这两种操作需要其他的方法

  • 强制对齐，使用pack(push, x)代表按照x字节对齐，把这个x具体数字 push到堆栈中。然后在想对齐的结构体之后把这个x再pop出来，取消x字节对齐模式，恢复正常对齐
  • 取消对齐，还是可以使用pack，push1，代表对齐边界是1字节，也就是代表紧密模式

fence

  • fence.i：告诉CPU i-cache中的指令已经失效，加载指令需要从内存中加载进i-cache
  • fence r, r: 读-读内存屏障 fence之前的read全部执行完成之后，才会继续执行下面的read
  • fence iorw, iorw：它强制 CPU 在执行这条指令之前的所有读写操作（包括IO设备：主机PCIe IP，NAND flash）必须全部完成，才能开始执行这条指令之后的任何读写操作。
  • fence rw, rw: 和上面的iorw不同的是，rw只针对内存读写，不涉及IO设备的访问读写

sync

**asm volatile("sync");** 流水线同步指令。也是RISC-V指令集，确保发出这条命令以前的所有指令都完成了提交和全局更新，也就是所有的core都可见。
