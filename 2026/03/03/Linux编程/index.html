可以把它理解成操作系统的“全局备忘录”或“快捷方式”。

网络编程

服务端和客户端之间的数据传输，需要依靠协议（TCP、UDP 分别是可靠传输和不可靠传输协议）

在网络通信中，我们还是使用文件传输来写程序

而传输使用的是**套接字建立连接 **，Socket 是操作系统提供的一种机制，它是对网络中不同主机上应用程序之间进行双向通信的端点的抽象。

ex. :一个 Socket 通常用一个组合来表示：<IP地址:端口号>。

服务器要做的事情是被动的相应请求，主要使用socket创建fd，bind绑定fd和ip端口，listen监听这个ip端口，accept接受客户端发来的链接， send和receive发送和接受数据

客户端要做的事情是主动的发送请求，同样还是使用socket创建fd，connect建立链接，send和receive收发数据

多线程编程

采用多线程编程的原因主要是为了使得我们的程序有更高的并行性

本节的示例是开启两个线程，一个是接收线程 一个是打印线程，

接受线程接受数据，接受到数据之后唤醒打印线程，打印线程打印处理

主要有两种实现方法： 条件量/信号量 + 互斥量

  • 条件量是一个等待队列。它本身不存储状态，只负责“挂起”和“唤醒”线程。
  • 信号量是一个计数器 (整数)。它存储状态（剩余资源数），线程根据计数值决定是继续运行还是阻塞。

1.信号量+互斥量

由于这两个进程公用同一个buf，所以会存在资源争用的情况，所以需要进行同步机制

使用信号量可以在接收线程接收完数据之后唤醒打印线程

使用互斥量可以让两个线程互斥访问buf，保证数据可靠性

串口

串口全称叫异步首发传输器（UART）简称串口，它的作用是：

  • 调试：移植应用时，使用串口查看打印信息
  • 外接各种模块：GPS 蓝牙模块

串口的内部主要有

  • TXD：输出引脚 用于输出数据
  • RXD：read引脚 用于读取数据
  • GND：公共参考电平（0V）它是信号传输的“基准线”

串口数据是通过电平高低，逐位发送，串行发送

使用mobaxterm连接开发板，需要填的信息主要是波特率

  • 波特率：发送一个数据位的时间（每一个数据位的发送占时），例如波特率为115200的时候，
    • 1s传输的数据是115200bit的数据
    • 如果按照btye计算，在8n1（8个数据位，没有校验位，一个停止位）的情况下，1byte的数据需要传输10bit（start（1），data（8），stop（1），1s传输的字节数是 1/(10/115200) = 11520字节

串口之间的数据传输路径大概是：串口1 -> 串口2 -> 驱动 -> 行规程 -> app(shell)

tty：

它是用户与操作系统内核交互的接口设备。

负责接收你的键盘输入，并将其发送给内核；同时负责接收内核的输出，并显示在你的屏幕上。

数据流：用户键盘 -> TTY设备 -> shell进程 -> 内核

对于UART编程的套路就是 open-> 设置行规程 ->read/write 主要难点是设置行规程

I2C

I2C是一种同步、串行、半双工的通信协议，主要用于微控制器（MCU）与各种低速外围设备（如传感器、EEPROM、实时时钟、LCD驱动器等）之间的短距离通信。

  • 写操作

I2C传输数据的时候，由主芯片发出一个start信号，接收方设备回应之后，建立连接开始传输数据。

主设备发送数据之后等待回应，每传输1bit都需要等待回应，发送完成之后主芯片发送停止信号。

  • 读操作

与写操作相同，只不过读操作是 从设备 1bit发送信号 主设备1bit接收

I2C协议传输数据需要两条线 SCK是传输时钟 SDA是传输数据

以下是I2C协议的一些重要结构体

i2c_msg 是最直接描述一次 I2C 传输消息的结构体。当你调用 <font style="color:rgb(6, 10, 38);">i2c_transfer()</font> 函数时，传递的参数就是该结构体的数组。它定义了“要发什么数据”、“发给谁”、“是读还是写”。

在驱动中构造一个或两个 <font style="color:rgb(6, 10, 38);">i2c_msg</font> 结构体（例如：先写寄存器地址，再读数据），然后传递给 <font style="color:rgb(6, 10, 38);">i2c_transfer()</font>。

i2c_client 结构体代表挂在 I2C 总线上的具体物理设备（如某个温度传感器）。在设备驱动（Device Driver）中，你通常会通过 <font style="color:rgb(6, 10, 38);">probe</font> 函数拿到这个结构体的指针，并从中获取设备地址和适配器信息。

还有I2C 控制器硬件

SMBus

SMBus是I2C协议的子集 其对I2C协议进行了限制

  • VDD电压不同
  • 限定了最小时钟频率
  • 地址回应：设备接收到地址之后是否需要发出回应信号
  • REPEATED START：在数据发送结束之后不用发出P信号，而是直接发出S型号代表下一个请求的开始

驱动

驱动（Driver）是告诉 OS 如何操作具体的硬件（如网卡、屏幕、传感器），是OS的一部分

如何编写驱动程序：

  1. 确定主设备号
  2. 定义自己的file_operations结构体
  3. 实现对应的open/read/write等函数，填入file_operations结构体
  4. 把file_operations结构体告诉内核: 注册驱动程序（register）
  5. 谁来注册驱动程序啊? 得有一个入口函数:安装驱动程序时，就会去调用这个入口函数
  6. 有入口函数就应该有出口函数:卸载驱动程序时，就会去调用这个出口函数
  7. 其他完善:提供设备信息，自动创建设备节点
