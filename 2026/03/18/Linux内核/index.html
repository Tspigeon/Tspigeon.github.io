Linux内核机制的学习博客

块设备驱动

块设备的定义是使用固定大小数据块进行寻址和访问的设备，以下是Linux0.11下内核中的预留设备号

总体功能：内核操作块设备是以逻辑块（1K）为单位，块设备控制器是以扇区（512B）为单位，所以两个控制器之间会有一个缓冲区。（有专门的缓冲管理程序）

以read操作为例，

  1. 需要read的进程等待，内核首先会到缓存区里面去找数据，
  2. 如果数据没有找到，就会调用读写函数，想块设备发送读操作
  3. 内核向块设备控制器发出读数据命令，生成块设备请求项 加入请求队列
  4. read到数据之后，块设备控制器把数据放到缓冲块中，并发出中断信号
  5. 内核收到之后 进程唤醒

块设备请求项

os管理块设备靠的是 内存中的块设备表 blk_dev[] 每种块设备都占一项 每一项的结构如下

第一个字段是函数指针：是请求项操作函数 硬盘是do_hd_request()，请求处理函数

第二个字段：当前操作的request

内核发出读写操作时，缓冲管理程序（ll_rw_block()函数）根据内核提供的 操作命令和设备号 创建一个块设备请求项，然后加入请求队列中。这个请求队列最深为32项

以下是request结构体

TIPS：可以发现request是一个数组但是还有next指针，这是因为这样数据排布可以同时利用数组和链表的优点

  1. 数组特性：分配地址快-不用malloc，访问快-已知下标的情况下可以直接访问
  2. 链表特点：增删通过指针实现，比如0 1位置有数据 现在想在0 1之间插入数据 data，就可以把data还是放在下标2的数组位置，但是操作next指针实现逻辑上的数据顺序改变

块设备操作

系统控制主要由三个部分组成，系统 设备控制器 驱动器

三者之间的交流步骤是

  1. 首先系统指明控制器在执行命令结束而引发的中断过程中应该调用的C函数，然后向块设备控制器发送读、写、复位或其他操作命令；（先置中断函数 再发送命令）

  2. 当控制器完成了指定的命令，会发出中断请求信号，引发系统执行块设备的中断处理过程，并在其中调用指定的C函数对读/写或其他命令进行命令结束后的处理工作。

  3. 对于写盘操作，系统需要在发出了写命令后（使用 hd_out()）等待控制器 给予允许向控制器写数据 的响应，也即需要查询等待控制器状态寄存器的数据请求服务标志DRQ置位。一旦DRQ置位，系统就可以向控制器缓冲区发送一个扇区的数据。

  4. 数据从控制器缓冲区写到驱动器中之后，控制器还会产生一个中断，用于判断系统是否还需要写数据，如果需要系统就重复 a 操作。

  5. 对于读盘操作，系统首先发送要 read 哪些数据。然后系统端等待控制器的中断，控制器从驱动拿到数据之后，将一扇区的数据放在控制器的缓冲区，然后触发中断，数据被迁移到系统缓冲区，系统更新剩余 read 扇区的数量和 read 指针等；如果还有数据没有 read 上来 系统就等待控制器的下一个中断。

内核空间和用户空间的切换

物理地址的起始1MB

1MB 以下的物理内存是 x86 架构在硬件层面上就规定好的“不动产”。它里面装的是：

  • 中断向量表（IVT）
  • BIOS 数据区（BDA）
  • VGA 显存（用于文本模式显示）
  • 设备 ROM（BIOS、显卡 BIOS 等）

这部分区域在物理上是内核直接管理的。在操作系统启动完成后，这片区域要么被内核标记为“保留”（Reserved，禁止任何程序使用），要么被用作内核态专用的 DMA 区域（因为老旧设备只能访问这片低端物理内存）。

地址映射

32位寻址和64位寻址

代表CPU进行寻址的大小位数，直接反映会C语言指针的大小，32位下的指针大小最大位32bit，寻址大小是4G，这同样限制了内存大小。

这个的物理意义是，CPU只有32根引脚，输出的电平组合只有2^32

随着内存大小越来越大，CPU转换成64根引脚，能够寻址的内存空间就越来越大。

逻辑地址，线性地址，物理地址

逻辑地址通过全局描述符表GDT和局部描述符表LDT映射成为CPU可以使用的线性地址，线性地址通过页表（一级页表、二级页表）转换成物理地址

以Linux中的任务0为例：

CPU 使用 段选择子（在代码或数据寄存器中）索引 GDT

GDT表会保存LDT表的信息和任务0的状态，LDT表中会保存任务0数据和代码的段基址，由于段基址为 0，虚拟地址（逻辑地址）直接等于线性地址。

虚拟地址转换成线性地址用于CPU寻址，CPU找具体数据的时候需要将线性地址经过页表转换成物理地址到内存或者外存中查找数据

写时复制、需求加载

写时复制要求fork出来的子进程在接收到写入之前共享父进程的用户空间

需求加载其实是懒加载机制，就是内存页面被需要的时候才触发缺页然后把页面加载进来。

页表项

线性地址结构

具体页表结构：前12位是权限和有效性信息

  • 页表项（PTE）的属性定义：
    在 x86 架构的分页机制中，每个页表项（32位）不仅包含了物理内存页的地址，还包含了权限属性位：

  • **Bit 0 (P)**：存在位（Present）。1 表示该页在内存中。

  • Bit 1 (R/W)：读写位（Read/Write）。1 表示可读可写，0 表示只读。

page操作

get_free_page()函数

注意的点：

  • register代表数据将会被放在cpu寄存器中
  • asm(“ax”)代表__res变量将会和ax寄存器关联
  • __asm__用于在gcc中内嵌汇编代码
  • movl %%edx,%%eax\n\t 这句汇编代码将最后的数据结果放到了eax寄存器中，也就是我们前面的ax寄存器（eax是ax的拓展，ax是eax的低16位）

free_page函数：用于释放一个page的空间

基于free_page还有free_page_tables释放一个连续空间的内存，主要提供from(起始线性地址)，size(释放的地址长度)，需要注意size为对4KB向上取整释放内存页面

共享策略

copy_page_tables()函数：用于copy一定size的内存空间

复制页目录表项和页表项。复制指定线性地址和长度内存对应的页目录项和页表项，从而被复制的页目录和页表对应的原物理内存页面区被两套页表映射而共享使用。复制时，需申请新页面来存放新页表，原物理内存区将被共享。此后两个进程（父进程和其子进程）将共享内存区，直到有一个进程执行写操作时，内核才会为写操作进程分配新的内存页（写时复制机制）。

参数from（从哪里复制）、to是线性地址（复制到哪里去），size是需要复制（共享）的内存长度，单位是字节。

put_page()：将物理内存页映射到线性地址

主要工作建立将物理页的数据（地址，权限位）放到页表项中。若成功则返回物理页面地址。

写时复制的数据一开始会被共享，设置为只读，后面遇到写入的时候才会分配页面写入

un_wp_page() 就是将遇到写入之后的操作，传入的参数是一个具体的页表项

  1. 首先判断内存页是否被共享

  2. 如果没有被共享 直接从只读变为可写

  3. 如果被共享 跳转2

  4. 寻找空闲内存页 进行复制操作

真正写时复制的写保护解除的时候，调用的函数是do_wp_page，do_wp_page传入的一个线性地址

线性地址转换成页表项地址之后，执行un_wp_page

get_empty_page() 不仅仅是get_free_page 而且还调用了put_page，建立了线性地址和物理页地址的联系

try_to_share，对给出的地址处的页面进行共享处理，将进程p中的address位置的页面 共享给 当前进程

share page()主要用于缺页发生的时候，试图找到一个进程，它可以与当前进程共享页面（可以直接换进 不用换出）。参数address 是；当前进程数据空间中期望共享的某页面地址。

do_no_page() 执行缺页处理，页面异常中断处理过程调用的函数

总体来看 这个缺页中断的处理逻辑：

  1. 找到缺页页面的逻辑地址

  2. 判断逻辑地址范围

  3. 在进程外 get_empty_page

  4. 在进程内

  5. 首先看是否可以共享

  6. 不能共享就分配内存，（同时保持页面干净防止尾部数据错乱 end_data是文件结束的地址，非4K对齐）

  7. 最后建立线性地址和物理页面联系

mem_init() 内存初始化函数 Linux0.11中的内存大小是16MB，主要功能是设置4-16MB的主存以及mem_map[]数组

page.s

该文件包括页异常中断处理程序（中断 14)，主要分两种情况处理。一是由于缺页引起的页异常中断，通过调用 do_no_page(error_code, address)来处理；二是由页写保护引起的页异常，此时调用页写保护处理函数 do_wp_page(error_code, address)进行处理。其中的出错码(error_code)是由 CPU 自动产生并压

入堆栈的，出现异常时访问的线性地址是从控制寄存器CR2中取得的。CR2是专门用来存放页出错时的

线性地址。

页出错异常处理

线型地址到物理地址过程中会触发页异常中断，主要分为以下两种情况

  • CPU发现页目录项和页表项的存在为是0 不存在
  • 当前进程没有访问权限

页异常中断 CPU 主要保存下面两种信息

  1. 放在堆栈上的出错码。该出错码指出了异常是由于页不存在引起的还是违反了访问权限引起的；在发生异常时CPU的当前特权层；以及是读操作还是写操作。出错码的格式是一个32位的长字。但只用了最后的3个比特位。分别说明导致异常发生时的原因：
  • 位2(U/S)-0 表示在超级用户模式下执行，1 表示在用户模式下执行；
  • 位 1(W/R)- 0 表示读操作，1 表示写操作；
  • 位 0(P) - 0 表示页不存在，1 表示页级保护。
  1. CR2(控制寄存器 2)。CPU 将造成异常的用于访问的线性地址存放在 CR2 中。异常处理程序可以使用这个地址来定位相应的页目录和页表项。如果在页异常处理程序执行期间允许发生另一个页异常，那么处理程序应该将CR2压入堆栈中。
