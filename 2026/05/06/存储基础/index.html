存储知识总结

存储体系结构

存储整个过程的体系结构由下图所示：

存储中的三座大山：磁盘、内核文件系统、分布式文件系统/数据库应用程序，两种桥梁：driver(联通磁盘和文件系统)和VFS(连接应用程序和文件系统)

SPDK：

接管磁盘，实现了用户态文件系统，上层还是VFS提供具体的系统接口，SPDK代理NVMe不使用具体的接口

fuse：

用户空间文件系统” (Filesystem in Userspace)。FUSE 是一种机制，它允许开发者在用户态（User Space）而不是内核态（Kernel Space）编写和运行文件系统。

UFS

轻量级的SSD与主机交互协议，用于手机存储芯片和车规芯片

UPIU数据格式

LU

eMMC

NVMe:

NVM Express（NVMe），或称非易失性内存主机控制器接口规范

NVMe SSD可以分为三部分，host端的驱动（NVMe官网以及linux、Windows已经集成了相应的驱动）、PCIe+NVMe实现的控制器以及FTL+NAND Flash的存储介质。

  • NVMe控制器：NVMe控制器实质上为DMA + multi Queue，DMA负责数据搬运（指令+用户数据），多队列负责发挥闪存的并行能力。

NVMe多队列：

相比于SATA/AHCI协议中，所有CPU核心都需要竞争一个命令队列

NVMe 驱动会尝试为每个 CPU 核心（或逻辑处理器）分配一个独立的 I/O 提交/完成队列对，以最大化并行处理能力。但这受到硬件限制和操作系统调度策略的影响。而 NVMe 支持高达 64K (65,535) 个 I/O 队列，每个队列深度也能达到 64K。

NVMe分配队列的方式有两种，一个是每个CPU核心一个队列，或者也可以一个线程一个队列

Admin队列和IO队列：
Admin队列是控制流、IO队列是数据流

Admin提交和完成队列：

Admin队列在控制器初始化的时候必须存在，他会用于存放所有管理和控制命令（创建删除IO队列，附加分离namespace，获取日志，固件激活，控制器复位），

这个队列通常只有一对，而且队列深度较浅

IO提交和完成队列：

存放数据命令：read write flush，可以最多存放6k对，主机软件可以动态创建他们

NVMe命令：

  • admin命令：创建/销毁队列 SQ（submit，主机向设备发送的请求）和CQ（complete，设备向主机发送）SQ和CQ都位于主机内存中
  • I/O命令：write/read，flush（将缓存中的数据刷到SSD），数据校验
  • 命令格式：

opcode是指定要执行的操作，01h是flush，02h是写，05h是读

fuse是指定这个命令是否可以融合

NSID是命名空间的ID代表命令作用于哪个命名空间（命名空间将一个物理的SSD分为了逻辑上不同的SSD）

CID是命令标识符，用于在CQ中匹配完成的状态

数据指针是存放数据在主机内存中的位置，NVMe支持两种内存寻址方式 PRP（Physical Region Page）和SGL（Scatter/Gather List）：

  • PRP（物理区域页）：这是NVMe 1.0版本引入的基础机制。它将主机内存按固定大小的物理页（通常是4KB）进行划分，每个PRP条目是一个64位的物理地址指针，指向一个具体的物理页。当数据传输跨越多个页时，会使用PRP列表（PRP List）来串联这些页的地址。它的优点是硬件实现简单，但缺点是需要内存页对齐，对于非对齐或小尺寸数据传输效率较低。
  • SGL（分散/聚集列表）：这是NVMe 1.1版本引入的更灵活、更高效的机制。SGL由一系列16字节的描述符组成，每个描述符不仅包含物理地址，还包含该段数据的长度信息。这使得SGL可以精确描述任意大小、任意起始位置的数据块，无需强制页对齐。SGL还支持链表结构，可以描述非常复杂和非连续的内存布局，特别适合处理大文件、数据库操作或虚拟机环境中的I/O请求。
  • 具体实现
  1. PRP：创建PRP列表寻址，每一个条项包含（PRP1，PRP2）这两个都是数据指针，指向内存物理页地址。当写入数据大小不到一个内存页的时候，PRP1指向地址，PRP2为0代表空；写入数据在1-2个内存页的时候，PRP1和PRP2都指向地址；写入数据大于两个内存页的时候，PRP1指向地址，PRP2指向下一个PRP Entry
  2. SGL：SLG链表的单个条项是一个SGL描述符：包括地址、长度、标识（标识这是数据、指针还是下一个段的开始）

Compare Operation

比较命令 读取逻辑块的数据并和主机数据缓冲区中的数据进行比对

  1. 比较成功 返回到 CQ
  2. 比较失败 会返回代表失败的状态码（status code）

Fused Operation

Fused Operation 并不是一个单一的新指令，而是由主机（Host）将两条独立的命令在提交队列（Submission Queue）中相邻放置，并通过命令头部的 Fused Operation 字段（Dword0 的 09:08 位）将它们标记为一个不可分割的原子单元。

fused operation 又叫做 compare and write fused operation 会经过以下阶段：

  1. Compare（比较）阶段：控制器首先读取指定逻辑块地址（LBA）上的数据，并与主机提供的数据缓冲区进行比较。如果开启了端到端数据保护，还会对元数据和保护信息（PI）进行校验。
  2. 条件写入（Conditional Write）阶段：
  • 如果比较成功（匹配）：控制器立即在相同的 LBA 位置执行写入操作，将新数据写入介质。
  • 如果比较失败（不匹配）：写入操作将被直接中止（Aborted），整个融合操作以错误状态结束，磁盘上的原有数据保持不变。

Copy Command

用于将范围内的源逻辑块数据 复制到 连续的目标逻辑块范围

Verify Command

读取 data 和 metadata 上来，验证数据完整性

完成之后返回 CQE，Verify command 的 status code 采用的是 read command 返回的状态码集

Write Uncorrectable

类似于 trim，将一段逻辑块置为无效

Write Zeros

WRITE Zeroes命令用于将一系列逻辑块设置为零，

DB：

物理位置：它位于 SSD 的控制器内部（属于 SSD 的寄存器空间）。

逻辑本质：它是一块主机可以通过 PCIe 总线直接访问的内存区域（MMIO）。

核心功能：它是主机和 SSD 用来“喊话”的通道。因为 SQ 和 CQ 通常位于主机的内存（DRAM）中，SSD 和主机无法时刻盯着对方的内存看（那样太费性能），所以通过“按门铃”来告诉对方“有新情况了”。

主机先把指令写入到主机内存中的 SQ（提交队列） 里。写完后，主机通过 PCIe 总线，向 SSD 的 SQ Tail DB 寄存器写入一个新的数值SSD 执行完指令后，把结果放回了主机内存的 CQ（完成队列），并给 CPU 发了一个中断信号。

doorbell 配置的合法性检查：

在 NVMe 协议中，Doorbell（门铃）配置的合法性检查是控制器固件或硬件逻辑为了确保主机（Host）写入的 Doorbell 寄存器值有效、安全且符合协议规范而进行的一系列验证步骤。

Doorbell 机制是 Host 与 Controller 之间通信的核心同步机制：

  • Host 写 SQ Tail Doorbell (SQTD)：告诉控制器“我有新的命令提交了，快来取”。
  • Controller 写 CQ Head Doorbell (CQHD)：告诉主机“我已经处理完一些命令了，你可以回收 Completion Queue 的空间了”。

所谓的“合法性检查”，通常包含以下几个关键维度的验证：

  1. 队列 ID (QID) 的有效性检查

当 Host 写入 Doorbell 寄存器时，首先必须指定是哪一个队列（Queue ID）。

检查内容：验证 Host 访问的 QID 是否在控制器支持的范围内（例如 0 到 N−1 ，其中 N 是最大队列数）。

目的：防止 Host 访问不存在的队列，导致内存越界或系统崩溃。Admin Queue 通常是 QID 0，IO Queues 从 QID 1 开始。

  1. Doorbell 值的单调递增与回绕检查

NVMe 协议规定，Doorbell 的值必须是单调递增的（模队列深度）。

检查内容：

SQ Tail Doorbell：新写入的值必须比上一次记录的值大（考虑到回绕）。如果 Host 写入的值比当前值小（且不是正常的回绕），说明 Host 驱动逻辑错误。

CQ Head Doorbell：同理，Host 更新的 CQ Head 指针也必须向前移动。

目的：防止 Host 重复提交同一个命令，或者跳过某些命令，保证数据处理的顺序性。

  1. 队列深度边界检查

这是最关键的检查之一。

检查内容：Doorbell 的值不能超过该队列初始化时协商好的队列深度。

例如，如果 Submission Queue 的深度是 64，那么合法的 Doorbell 值范围应该是 0∼63 。如果 Host 写入了 64 或更大的值，这就是非法的。

目的：防止 Host 覆盖尚未处理的旧命令（Overwrite），或者访问超出分配内存范围的区域。

  1. 队列状态检查

检查内容：在进行 Doorbell 更新前，检查该队列是否处于就绪状态。

对于 SQ，必须已经通过 Create SQ 命令成功创建并启用。

对于 CQ，必须已经通过 Create CQ 命令成功创建。

目的：防止 Host 向一个未初始化或已删除的队列发送指令。

中断：

NVMe控制器完成命令之后，他会使用中断通知主机，中断类型有以下三种

传统PCI中断：需要主机轮询识别中断源，效率低
MSI：允许设备发送内存写事务（TLP）到主机内存，用于传递中断信息，更快更可靠

MSI-X：MSI增强版，支持多个独立的中断向量和目标地址

NVMe规范强烈推荐使用MSI -X。它允许为每个I/O队列分配一个独立的中断向量。这减少了核间中断（IPI）的开销

数据保护：

数据传输过程中可能出现问题，为了保护数据，NVMe支持两种数据保护方式

  1. DIF：每512字节配合 8字节的保护信息，一般是包含CRC校验和其他保护字段，保护信息随着data一起写到SSD中
  2. DIX：保护数据和data分开存储，传输过程中一起传输，但是最后存储在不同的物理位置上

NVMe工作流程：

  1. 系统通过内存中的PCIe配置空间发现NVMe控制器，

  2. 首先os会询问NVMe设备需要多大主机内存空间，NVMe设备通过BAR(base address register)回答os需要多少内存空间，

  3. 然后系统会在PCIe地址空间中找到一块空闲区域，把空间区域的基地址写回BAR寄存器，

  4. 最后只要CPU想访问这块内存，主板上的路由就知道把请求转发给NVMe设备（就是系统IO->设备IO IO栈的转换）

  5. 为NVMe设备分配通信窗口

  6. 系统根据 BAR 提供的地址，在 CPU 的内存地址空间中划分出来的一块区域。这块区域实际上对应的是 NVMe 控制器内部的物理寄存器

  7. 窗口被打开之后，CPU就会想读写普通内存一样，直接向这个地址写入数据

  8. 写入的数据不会写入内存条，而是通过PCIe总线发给NVMe控制器

  9. NVMe 驱动就是通过这个“窗口”来执行核心操作的，比如：写 Doorbell（门铃）寄存器，告诉硬盘有新命令了。读状态寄存器：询问硬盘命令是否完成。

  10. 驱动程序将命令放入主机内存中的SQ，然后通过一个内存写事务TLP写SSD的DB，用于通知控制器

  11. 对于多队列的NVMe，主机内存中的SQ是每个队列一个SQ

  12. 完成队列（CQ）的数量是灵活的，但通常远少于提交队列（SQ）的数量。但 CQ 通常是按照 CPU 核心数 或者 中断向量数 来配置的。

  13. 控制器获取命令，如果需要传输数据，则发起DMA操作，通过内存读TLP（对于读命令）或内存写TLP（对于写命令）在主机内存和控制器缓冲区之间搬运数据。

  14. SSD控制器检测到某一个DB来数据了，然后进入主机内存的SQ中拿命令（DB与SQ是一一对应关系）

  15. 如果是read操作（主机从SSD读取数据）：

  16. SSD控制器通过DMA从主机内存中的SQ中获取read命令，其中包含：要读取的数据、读取之后放在主机内存的哪一个位置

  17. SSD内部将数据从NAND上读取上来

  18. SSD控制器将读取上来的数据组成一个内存写事务（TLP）

  19. 这个TLP随着PCIe总线写到对应的内存位置

  20. 最后触发中断，通知CPU数据写好了，CPU来取数据

  21. 如果是write操作：

  22. SSD控制器通过DMA 发起读TLP 获取SQ中的write命令，命令中包含要写到flash中的内存数据的地址

  23. SSD内部组装一个读TLP，到SQ给定内存地址中去读取数据

  24. 主机内存控制器收到TLP，将数据通过PCIe总线发送给SSD

  25. SSD接收到数据，写入NAND

  26. 控制器将完成状态写入主机内存中的CQ，然后通过MSI-X中断TLP 通知驱动程序。

  27. 往CQ中写入的数据是一个固定大小（一般为16字节）的CQE。其中字段包括：

  28. Command Specific Parameter：4字节大小，命令特定参数，普通成功读取情况下是0

  29. SQ Head (SQH)：2字节，SQ队头指针，SSD告诉CPU，这个SQ执行到哪里了

  30. SQ ID (SQID)：2字节，执行的哪一个SQ

  31. Command Identifier (CID)：2字节，命令标识符，CPU发命令的时候产生，SSD完成之后需要返回

  32. Status Field (SF)：2字节，状态字段，包括P：回卷，即CQ是否转了一圈，SC：具体执行结果，0是成功、其他值代表错误

  33. 完成确认，CPU告诉SSD，我知道你完成了

  34. CPU封装内存写TLP

  35. PCIe总线传输TLP到CQ的DB中

  36. SSD读取CQ DB，知道CQ完成已经被CPU处理

NameSpace：

命名空间，为了应对多租户的情况，是 NVMe 暴露给主机的逻辑空间，一个 NS 包含 2 的幂次方个 LBA（或者说逻辑块）

  1. NVMe 协议层面：Namespace = 原始逻辑块设备（逻辑卷）
    对 NVMe 控制器而言，Namespace 是一个拥有独立 NSID、容量、LBA 格式的非易失性存储块集合。
    主机通过 NVMe 命令（Read/Write/Compare 等）直接以 NSID + LBA 的方式访问它。
    此时它只是一个原始的块设备，没有分区表、没有文件系统，类似于一个“裸盘”。
  2. 操作系统层面：Namespace → 块设备节点 → 分区/文件系统
    当主机（如 Linux）枚举到 NVMe Namespace 后，会将其映射为操作系统的块设备节点：

在此基础上，操作系统可以进一步划分：
分区：在 /dev/nvme0n1 上创建 /dev/nvme0n1p1, /dev/nvme0n1p2…（windows 下的 C 盘，D 盘）
文件系统：在分区或整个 Namespace 上格式化为 ext4/xfs/btrfs 等。
LVM/RAID：将多个 Namespace 组合成逻辑卷或软 RAID。

Sanitize、Firmware管理：

sanitize operation（安全擦除）：安全的、不可恢复的擦除所有用户数据，这是管理命令，执行全盘擦除格式化。SSD正常的erase操作不存在于NVMe指令中，而是交给FTL管理

Block Erase：块擦除

overwrite：擦除之后写

Crypto Erase：删除加密密钥，使得数据无法解密，从而使得flash中的数据无效

固件Firmware管理：

固件中有SSD的全套控制软件，他存储在ROM或者Flash中，包括：前端接口模块，FTL核心模块，后端闪存管理（ECC纠错，BBM坏块管理、读写电压调节）

多个固件槽：控制器支持多个固件镜像槽位。

原子更新：通过单个固件下载命令传输整个固件镜像。

激活调度：可以立即激活或计划在下次重启时激活新固件。

回滚保护：确保在固件更新失败时能回退到已知正常版本。

SPDK代理NVMe：

SPDK是由英特尔发起的，用于加速NVMe SSD作为后端存储使用的应用软件加速库。这个软件库的核心是用户态、异步、轮询方式的NVMe驱动。

SPDK 完全不使用 Linux 内核的 NVMe 驱动（nvme.ko），但它内部包含了一套自己实现的、运行在用户态的 NVMe 驱动程序。SPDK用户态驱动会暴露对应的API给应用程序来控制和操作硬件设备。

PCIe总线：

PCIe总线分为三层，物理层，数据链路层，处理层。通过包来转发数据。NVMe协议定义的内容相当于PCIe的上一层应用层，处于应用层。PCIe给NVMe提供了底层的抽象。

PCle分层：PCle通信分为三层：

事务层，数据包格式是TLP，主要包括NVMe命令和数据，是核心数据包

数据链路层，数据包格式是DLLP，有用于链路管理的信息 ACK，NAK和流量控制信息

物理层，数据包格式是PLP，有用于帧同步和链路训练的信息

PCIe配置空间：SSD插入系统需要进行配置，识别是什么设备，这就是PCIe配置空间的作用，配置空间保存在内存中大小为4KB

而数据包格式除了上面提到的三种，还有CPL和CPLD

在 PCIe 协议中，CPL 和 CPLD 是两种用于响应“非发布事务”（Non-Posted Transaction）的完成包，它们都属于 Completion TLP。

  • CPL：Completion without Data，即不带数据的完成包。它仅用于确认一个写操作或配置/IO读操作已成功执行，不包含任何数据载荷。例如，当主机向设备发起一个 Memory Write Request 后，设备处理完毕会返回一个 CPL 包，表示“写操作已完成”。
  • CPLD：Completion with Data，即带数据的完成包。它专门用于响应 Memory Read Request，除了包含完成状态外，还携带了从设备内存中读取到的实际数据。例如，主机请求读取 SSD 控制器 CMB 空间中的某个地址，设备在返回 CPLD 时会将该地址对应的数据一并传回给主机。

概述

以下是PCIe总线整体架构图，主要包括三个部分，PCIe_IP(主机)，PCIe_ADP(适配器)，PCIe_APP(PCIe设备)

PCIe_ADP (PCIe Adapter) 是 PCIe_APP (PCIe Application) 和 PCIe_IP 的适配模块，模块主要功能是和 PCIe_IP 进行交互，包括将 PCIe_APP 发起的 Dma 读（其实就是SQE read）、写和 CPLD 发送至 PCIe_IP。将 Host 下发的 Bar 访问发送至 PCIe_APP，将 PCIe_IP 内部 Dma 发起的读写操作发给 AXI 总线，负责管理 FW 和 Host 间的 MCTP 报文交互通道，以及管理 Msix Table （中断表）和中断控制。该模块还需要监测 PCIe_IP 的各种状态，当收到 FLR, Link down 等事件时，向 FW 发起中断。

  • **ADP_TRX (ADP Target Receive)**：该模块处理 PCIe_IP Axi Master 口下发的读写请求，主要完成路由功能。Edma 发起的读写数据请求，会直接发往 AXI；访问中断 Msix Table 的请求，发给中断模块；访问 CMB 或者 HPI，发往 PCIe_APP；收到 VDM message(MCTP)，发给 ADP_MCT 模块；
  • **ADP_TTX (ADP Target Transport)**：该模块将 ADP_TRX 下发的读请求对应的各模块返回的数据调度后发给 PCIe_IP，来源有 APP，AXI 和中断模块。
  • **ADP_INT (ADP Interrupt)**：中断模块，管理 Msix/Pending Table、不同 VF 和中断资源 VI 的映射表，以及接收 ADP_MTX 发起的中断发送请求，将生成的中断以包的方式再送回给 ADP_MTX。
  • **ADP_MTX (ADP Master Transport)**：负责多路读和写（包括中断）的调度，并发送给 PCIe_IP 或者中断模块。
  • **ADP_MRX (ADP Master Receive)**：负责接收 DMA 读返回的数据，并返回给 PCIe_APP。
  • **ADP_MCT (ADP Mctp)**：负责接收和发送 MCTP 报文。

PCIe_APP 模块接收 NPB 模块的读写请求，根据地址判断请求是发往 CMB 还是 PCIe。如果是读请求则将返回数据分发给不同模块。同时该模块接收来自 Host 的协议寄存器和 CMB 空间的访问，如果是读请求需要回复 CPL 或者 CPLD。

其中CMB是SSD控制器内存缓冲区，SQ队列可以存放在这里，CMB可以直接被host cpu访问，不需要通过DMA十分快捷

  • **APP_TRX (APP Target Receive)**：该模块处理 Host 主动下发的读写请求，并根据地址判断是发往 NPB 的 HPI 还是发往 CMB 空间。
  • **APP_TTX (APP Target Transport)**：该模块回收 CMB 或 HPI 回来的数据（Host 读请求），并将完成包发送给 ADP 模块。
  • **APP_AXM (ADP AXI Master)**：和 AXI 的 Master 接口，负责读写请求的调度，做读写保序，适配和 AXI 的接口交互，以及从 AXI 回来的数据分发。
  • **APP_MTX (APP Master Transport)**：负责多路读和写的调度，根据地址判断是发往 CMB 还是 Host。
  • **APP_MRX (APP Master Receive)**：负责接收 DMA 读返回的数据，并将 CMB 和 PCIe 返回的数据进行重排序。

机制

SRIOV：

SR-IOV（Single Root I/O Virtualization，单根I/O虚拟化） 是一种基于硬件的PCIe设备虚拟化技术，它允许一个物理PCIe设备（如网卡、SSD控制器）被虚拟成多个独立的“虚拟功能”（VF），每个VF都拥有自己的配置空间和资源，可被分配给不同的虚拟机或容器使用，从而实现高性能、低延迟的I/O共享。

例如使用SRIOV实现1个PF，32个VF的条件下

PF（Physical Function，物理功能）

PF是SR-IOV设备中真实存在的、完整的物理功能，通常由宿主机（Host）或管理程序（Hypervisor）直接使用。它负责：

  • 管理和配置所有VF；
  • 提供设备的完整功能集（如驱动加载、固件更新、全局配置）；
  • 作为VF的“父级”，为VF分配资源（如队列、内存、中断）。
  • 在你的例子中，“1个PF”意味着该SSD控制器有一个主管理接口，用于初始化和调度所有VF。

VF（Virtual Function，虚拟功能）

VF是PF通过硬件虚拟化技术“切割”出来的轻量级虚拟实例，每个VF可以独立分配给一个虚拟机或容器，使其“看起来”像拥有一个独立的物理设备。VF的特点包括：

  • 拥有独立的PCIe配置空间、BAR（基地址寄存器）、队列资源；
  • 不能直接管理设备，必须依赖PF进行初始化；
  • 性能接近物理设备，因为数据路径绕过软件虚拟交换机，直接走硬件通道。
  • 在你提到的场景中，“32个VF”意味着该SSD控制器可以为32个不同的虚拟机或业务实例提供独立的I/O通道，每个VF可绑定到特定的读写队列（如“读写各33个队列，共66个队列”），实现精细化的资源隔离和调度。

NO-SRIOV和SRIOV的区别在于一个是使用软件实现的多租户使用同一个PCIe设备，而SRIOV是在PCIe上通过网卡硬件实现的共享

一、资源分配模型：独占 vs 共享

NO-SRIOV：通常采用“设备直通”或“软件模拟”模式。一个物理设备只能被一个虚拟机独占使用，其他虚拟机无法访问该设备，资源利用率低。

SR-IOV：通过硬件虚拟化将一个物理设备拆分为多个“虚拟功能”，每个VF可独立分配给不同虚拟机，实现多租户共享同一物理设备，资源利用率高。

二、硬件抽象层级：软件层 vs 硬件层

NO-SRIOV：依赖Hypervisor或操作系统进行I/O虚拟化，数据包需在VM → Hypervisor → 物理设备之间多次拷贝和上下文切换，延迟高、CPU开销大。

SR-IOV：由网卡硬件直接提供VF，虚拟机驱动直接与硬件交互，绕过Hypervisor的数据平面处理，实现“零拷贝”和“近原生性能”。

三、性能开销：高 vs 极低

NO-SRIOV：由于软件模拟或半虚拟化（如virtio），每次I/O操作都需经过Hypervisor调度，引入显著延迟和CPU占用。

SR-IOV：硬件级虚拟化使虚拟机获得接近物理机的吞吐量和延迟表现，特别适合对延迟敏感的应用（如高频交易、实时视频流）。

四、隔离机制：逻辑隔离 vs 硬件隔离

NO-SRIOV：隔离依赖于Hypervisor的调度策略和内存保护，存在潜在的安全风险和性能干扰。

SR-IOV：每个VF拥有独立的PCIe配置空间、MAC地址、队列和中断，硬件层面实现强隔离，互不干扰，安全性更高。

link done：

它的核心作用是通知系统软件（如 CPU 或固件）：PCIe 物理链路已经成功建立并完成训练，设备可以开始正常的通信了。

同时也是PCIe的中断之一，fw检测到link done之后会做以下事情

  1. 停止DMA
  2. 阻断PCIe Bar（基地址寄存器）和DMA的数据通路
  3. 排空操作
  4. 等待PCIe IDLE
  5. 检查PCIe状态
  6. 初始化PCIe配置空间等
