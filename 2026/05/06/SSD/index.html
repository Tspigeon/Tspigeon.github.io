SSD Basic

FE前端

1 VCMD

全称 Vendor CMD，简称VU命令。指的是厂商自定义命令（Vendor Undefined/Specific Command）

  1. 固件写入与保护机制：SSD主控需要固件来驱动，出厂前厂商必须通过 Vendor CMD 将固件（包含运行温度检测、写入保护等指令）写入主控。例如，当环境温度超出标准范围时，SSD会触发写入保护机制以防止数据丢失。
  2. 出厂质量检测：它为出厂前的质量检测提供了调试和检测的快速通道。当SSD完成出厂检测后，该接口便功成身退，由于它不具备像 SATA/PCIe 接口那样常规传输数据的功能，因此常被误解为预留的“后门”，但实际上它是量产的必要步骤。
  3. 日常运维与调试：在系统运行中，主机可以通过发送 VU 命令让 SSD 执行特定操作，例如获取或清除 SSD 的运行日志、读取功耗、获取固件版本号等。在 Linux 环境下，常通过 nvme admin-passthru 等命令向设备发送自定义的 Admin Command 来进行底层调试。

硬件模块

DAC

DAC实际上就是一个环形缓冲区，软件和硬件各自维护一个头尾指针

DAC 分为TQ和RQ

TQ: 固件维护tail， DAC维护head， 用于发送命令到硬件加速模块

RQ: 固件维护head， DAC维护tail， 用于接收硬件加速模块的处理结果

(其实相当于head 为out， tail为in)

主要涉及到一个问题就是APB, 先解释一下什么是APB：

APB（Advanced Peripheral Bus）是一种广泛应用于集成电路（特别是片上系统SoC）中的低功耗、低带宽总线协议，属于ARM公司提出的AMBA（Advanced Microcontroller Bus Architecture）总线架构的一部分

APB主要用于以下场景：

  • 连接低速外设：如定时器、中断控制器、GPIO等。
  • 配置IP模块的寄存器：通过APB总线访问和配置各种IP模块的控制寄存器。
  • SoC设计中的系统级通信：作为低速总线，与高速总线（如AHB或AXI）协同工作，通过桥接器连接。

所以，我们可以知道APB是一个低速总线， 那么访问APB的时延就比访问AXI等高速总线大多了，这也是为什么DAC，一般会配置成让DAC将其维护的头或者尾指针推送到DTCM的方式，所以软件可以在低延时情况下访问

DFX_DacTqPrintMgt（qid） 查看TQ 管理信息

DFX_DacRqPrintMgt（qid）查看RQ管理信息

CMB

位于设备端，由 SSD 控制器管理，用于加速 I/O 命令提交和数据缓冲。

  • 降低延迟：传统模式下，主机向 SSD 提交 I/O 命令需通过 DMA 将命令写入设备内存，再触发门铃寄存器通知设备。若将 Submission Queue（提交队列）放置在 CMB 中，主机只需一次 PCIe 写操作即可完成命令提交，设备可直接从本地 CMB 读取命令，省去一次 DMA 传输，显著降低 I/O 延迟。

硬件支持：SSD 控制器需在 PCIe 配置空间中声明支持 CMB（通过 CAP.CMBS 位），并提供 CMBLOC（位置）和 CMBSZ（大小）寄存器供主机查询和配置。

主机启用：操作系统或驱动程序需设置 CMDMSC.CRC 位以启用 CMB，并根据 CMBLOC/CMBSZ 将其映射到虚拟地址空间。

应用场景：常用于高性能数据库、实时计算、AI 训练等对 I/O 延迟敏感的场景；也可作为 FTL（闪存转换层）元数据缓存，加速地址翻译和垃圾回收操作。

HMB

位于主机端，由主机内存提供，用于无 DRAM 的 SSD 存储 FTL 表等元数据，依赖主机内存带宽。

eFuse

eFuse (Electronic Fuse, 电子熔丝) 是芯片内部的一种一次性可编程存储器，通过熔断熔丝的方式永久存储数据。一旦写入（从 0 变为 1），就无法再修改。

主要用于写入一些出厂就固化的信息

还有安全信息：RSA公钥，密钥版本

调试信息：JTAG Boot UART串口锁定

硬件配置信息：PLL时钟配置

应用场景：

  • 安全启动：芯片上电时，BootROM 从 eFuse 读取 RSA 公钥哈希，验证 Bootloader 签名

  • 防回滚：通过 FW_SEC_VER_ID 防止降级到有漏洞的旧固件

  • 生命周期管理：

  • 制造阶段：JTAG/UART 开放

  • 量产阶段：烧录 JTAG_LOCK / UART_LOCK，关闭调试接口

  • 芯片溯源：通过 ATE 字段追踪每颗芯片的生产批次、位置、测试结果

命令解读

Trim命令

由于NAND Flash擦后写特性，所以需要及时标记无效数据 方便进行GC，但是数据有效还是无效SSD是不知道的。
所以Trim命令诞生，Trim命令是由主机发给SSD，目的是告诉SSD那些LPA已经无效。
SSD再接受了Trim命令之后，会更改映射表，如果空闲页面不足，也方便进行GC。

SSD状态

只读盘

代表只允许read操作，不允许write的command执行。

一般发生在GC的时候，后台GC时会对IO进行限流。第一步IO会降低，带宽会被分给GC操作。第二步，但当剩余空闲块的数量再次下降的时候，此时由于空闲块消耗速度还是大于GC回收速度，就会进入只读盘状态，FTL只会处理Read请求，避免空闲块耗尽。

控制盘

SSD控制器是7×24小时不间断运行的，但在以下特殊或极端情况下，控制器的底层调度策略和异常恢复机制会被深度触发（即“进入”控制盘）

  1. 异常断电或掉电保护触发时：
    当发生突然断电，SSD的掉电保护电容会提供短暂的应急电量。此时，控制器会立即进入紧急状态，主动调整调度策略，将缓存（如DRAM或SLC缓存）中尚未写入的L2P映射表等关键元数据迅速固化到闪存中，保全核心数据。
  2. 垃圾回收（GC）与主机写入发生冲突时：
    当后台正在进行繁重的垃圾回收，而主机又突然发来大量写入请求时，控制器会进入复杂的“仲裁与调度状态”。固件调度策略的优劣将直接决定此时SSD是否会出现严重的性能抖动或卡顿。
  3. 出现坏块或物理损伤时：
    当闪存颗粒老化产生坏块，或在工业/航天等极端环境下受到辐射损伤时，控制器会触发异常恢复机制，主动隔离受损区域，重新分配备用块，并修正映射表，以维持系统的持续运行。
  4. 集成AI能力的智能调优时（最新趋势）：
    在新一代（如PCIe 5.0）SSD中，控制器集成了AI能力。当识别到特定的工作负载（如AI场景、冷热数据交替）时，控制器会进入智能场景识别状态，动态优化数据调度逻辑，减小写放大，从而进一步提升性能和寿命。

机制学习

NTFS文件系统

windows NT家族使用的文件系统，替代了FAT文件系统成为windows主流
1.NTFS初始化
NTFS文件系统初始化磁盘的三个步骤分别是：初始化分区表，创建文件系统分区表，正常使用（read write del操作）

  • NTFS的分区方案有两种：
  1. MBR主引导记录：结构特点：位于磁盘第一个扇区（512字节），包含446字节引导程序 + 64字节分区表（最多4个主分区）+ 2字节结束标志“55AA”。
    核心限制：最大支持2TB容量；最多4个主分区（或3主+1扩展分区，扩展分区内可再分逻辑分区）；无冗余备份，一旦损坏可能导致整个磁盘无法访问。
  1. GPT（GUID分区表）特点有：容量跃升：采用64位逻辑块地址（LBA），理论支持高达18EB（1EB=100万TB）的存储空间，彻底解决大容量硬盘容量瓶颈；
    分区灵活性：默认支持128个主分区（Windows系统），无需扩展分区逻辑，每个分区分配唯一GUID标识符，避免冲突；
    数据可靠性：分区表在磁盘首尾各存一份备份，并通过CRC32校验机制实时检测错误，损坏时可自动恢复；
    安全增强：与UEFI配合实现安全启动（Secure Boot），抵御Bootkit等底层攻击。

    如图所示：示例中的分区表占34个LBA 在前34和后34个LPA都存放了一份 这里LBA是一个512字节的扇区，也就是磁盘的前34 * 512字节和末尾的34 * 512字节都是存放的分区表。
对比维度 MBR 分区表 GPT 分区表
最大磁盘容量 2TB（32 位 LBA 限制） 8EB（64 位 LBA 限制，无实际硬件瓶颈）
最大分区数量 4 个主分区，或 3 主分区 + 1 扩展分区（逻辑分区无上限） 默认 128 个分区（可扩展），无需扩展分区
分区标识 1 字节类型码（如 0x83 为 Linux 分区，0x0B 为 FAT32 分区） GUID（全局唯一标识，如 EBD0A0A2-B9E5-4433-87C0-68B6B72699C7 为 Linux 数据分区）
数据安全性 无备份，分区表损坏后数据易丢失；无校验机制 自带备份分区表；分区项含 CRC32 校验，支持自动修复
兼容性 支持所有 BIOS/UEFI 固件、所有操作系统（Windows XP 及以上、Linux 全版本） 仅支持 UEFI 固件（部分主板可开启 Legacy 模式兼容 BIOS）；Windows 7 及以下需特殊驱动，Linux 3.0+ 内核原生支持
引导方式 依赖 BIOS 引导，支持 MBR 引导加载程序（GRUB 1、LILO） 依赖 UEFI 引导，支持 EFI 引导加载程序（GRUB 2、systemd-boot）；支持安全启动
分区信息存储 固定在 LBA 0 扇区（512 字节） 分散存储（头部 + 备份），支持动态调整分区表大小
适用场景 传统 BIOS 主板、小容量磁盘（≤2TB）、旧系统兼容 UEFI 主板、大容量磁盘（>2TB）、新硬件（如 NVMe 硬盘）、安全启动需求

Ping-pong

Ping-Pong Buffer（乒乓缓冲区），一种在 SSD 主控中用于提升数据吞吐效率、实现流水线并行处理的硬件缓冲机制。

核心原理

  • 双缓冲交替工作：系统设置两个大小相等的缓冲区（Buffer A 和 Buffer B）。当一个缓冲区正在被“写入”时，另一个缓冲区可以同时被“读取”或“处理”，两者像打乒乓球一样交替使用，避免数据搬运过程中的空闲等待。
  • 消除串行瓶颈：在传统单缓冲模式下，数据必须“先写完再读”，存在明显的串行延迟。而 Ping-Pong Buffer 允许“写A的同时读B”，实现数据传输与处理的并行化，显著提升整体吞吐量。

使用：

  • 主机数据接收与 NAND 写入之间：当主机通过 PCIe 发送写命令时，数据首先被 DMA 搬运到 Buffer A；与此同时，FTL 可以将 Buffer B 中已准备好的数据发送给 NAND Flash 进行编程。当 Buffer A 填满后，立即切换为“可读/可写”状态，而 Buffer B 则开始接收下一批主机数据。
  • NAND 读取与主机回传之间：当从 NAND Flash 读取数据时，数据先加载到 Buffer A；此时，Buffer B 中的数据可以立即通过 PCIe 回传给主机。读取完成后，Buffer A 切换为“待回传”，Buffer B 开始接收下一批 NAND 数据。
  • 垃圾回收（GC）搬移过程：在 GC 操作中，需要同时“读取旧块数据”和“写入新块”。Ping-Pong Buffer 可以让 GC 引擎在读取源块的同时，将之前读取的数据写入目标块，大幅加速垃圾回收速度，减少对主机 I/O 的影响。

CRC

CRC是一种数据校验算法，结果是生成校验位

CRC校验主要用于数据从host传输到DDR的时候，数据会被进行一定处理，比如一开始的数据可能只有User Data+meta。但是经过NPB前端模块之后，数据可能会变成以下格式

其中最主要添加的数据就是uCRC和mCRC，一个用于保护userdata，一个用于保护FMD数据

CRC构造：由于CRC构造流程所以CRC一般都是紧贴后data存放

假设我们要发送的数据是 D ，约定的生成多项式是 G(x) ，其最高次幂为 r (代表CRC有R位)

  1. 数据扩展（补零）

在原始数据 DD 的二进制序列末尾，追加 r 个 0。

目的：给即将产生的 r 位余数（即 CRC 码）腾出位置。

  1. 模2除法

多项式的二进制和D进行XOR运算 （1和0相遇才为1）

  1. 生成校验码

模2除法最终得到的余数（长度必定为 r位），就是这段数据的 CRC 校验码。

例子：

假设我们要发送的数据是 1011，约定的生成多项式是 G(x)=x3+x+1（查表得）

  1. 确定参数：G(x) 最高次幂为 3，所以 CRC 长度为 3 位。 G(x)对应的二进制除数为 1011。
  2. 数据补零：在 1011 后面补 3 个 0，变成被除数 1011000。
  3. 模2除法：1011000和1011进行XOR运算得到000，CRC就是000了

ECC

ECC（纠错码）：轻量级修复，追求低延迟

不仅能检测错误，还能自动修复少量的比特翻转（例如 64位数据中坏了 1 个bit，ECC能直接算出并改回来）。如果坏得太严重（如2个bit），它只能报警，无法修复

SSD 控制器内部通常包含专门的 ECC 电路（ECC circuitry）或 ECC 引擎。当数据在主机与 NAND 闪存颗粒之间进行传输时，控制器负责拦截数据，并利用内置的算法模块进行编码或解码。此外，ECC 生成的校验码（冗余信息）并不会单独存放，而是与原始数据一起被写入到 NAND Flash 的备用区（Spare area）中。

  • 写入阶段（编码）：当主机向 SSD 写入数据时，控制器会自动计算该数据块的 ECC 校验码，并将数据与 ECC 校验码组合后，一并写入 NAND 闪存的存储单元及其备用区。
  • 读取阶段（解码与修复）：当读取数据时，控制器会重新计算数据的 ECC 值，并将其与存储在备用区中的原始 ECC 值进行比对

LDPC

LDPC是专门的纠错模块，企业级SSD中有专门的LDPC纠错硬件

主要是用于数据传输过程中的比特翻转问题，

LDPC（低密度奇偶校验码）的核心作用是“纠错”

  1. LPDC编码

针对一串原始数据，按照生成矩阵(G)定义的校验公式，生成校验数据。

校验公式的基本逻辑就是奇偶校验。

最后生成的数据由原始数据+校验数据组成

  1. LDPC解码

拿到原始数据以后，会根据校验矩阵，校验数据的正确性，如果都校验通过了，就完成了解码。

解码一般分hard decode和soft decode。

如果原始数据发生了部分bit翻转，那相关的校验公式有可能校验失败，这个时候就会通过 bit 翻转算法，和积译码算法等等。

dfx

主控芯片中一般会提供的一系列调试有关工具包的合集，构成了SSD固件的完整调试工具集

包含log注入：输出信息到log文件

内存映射打印：输出内存数据

寄存器导出：导出寄存器的数据；还有串口调试，SPI控制器调试，URAT调试等

SPKM

SBKM (Super Block Key Management，超级块键管理) 是 FTL 层中负责系统关键数据持久化存储的模块，专门管理 SSD 内部元数据、日志和系统信息的读写。

SBKM 是 FTL 的系统数据存储引擎，为 SSD 固件提供：

  1. 可靠的元数据存储：日志、配置、固件等系统关键数据
  2. 冗余保护：主副本 + Backup 副本 + XOR 校验
  3. 性能分级：Fast/Slow 区域适配不同访问频率
  4. 掉电安全：关键数据在掉电时保证写入完成
  5. 生命周期管理：擦除、磨损均衡、坏块处理

与 FTL 的用户数据路径（处理主机 IO）不同，SBKM 专注于 SSD 内部系统数据的持久化，是 SSD 可靠性和可维护性的基础设施。

PCIe

PCIe模块一般由FE端负责，一半分为两个部分：1.是PCIe上电初始化，2.是PCIe任务处理（复位，FLR中断<硬件重置>，linkdown中断<链路故障>）

1 链路初始化

初始化发生在复位结束信号和检测信号无误后，PCIe建立链路主要有五个步骤：PCIe phy寄存器的配置、PCIe配置空间寄存器的配置（部分PCIe Header寄存器）、ADP硬件模块、APP硬件模块以及使能LTSSM等

2 中断处理

  • PCIe任务处理：处理任务的时候首先要判断device有没有异常掉电。如果没有掉电，就会触发各种中断，这些中断处理函数中会调用PCIe task的状态机处理函数，从而推进task的执行。

  • 中断恢复：在启动中断处理task之后，PCIe需要从中断中恢复过来，才能执行第二个task

中断恢复流程如下：

  1. 切换CPU的频率为1600MHz（SDK_CpuClkDynamicCfg）
    配置MISC_CRG_CPU_CLK_CFG.fun_cpu_clksel为1
  2. Disable PCIe ADP Normal中断
    配置ADP_FATAL_INT_MSK.adp_top_fatal_int_mask为1
  3. Disable PCIe A Normal中断
    配置PCIE_A_NORMAL_INT_MSK.pcie_a_top_normal_int_mask为1
  4. 恢复PCIe Task。
